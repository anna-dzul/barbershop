# Вимірювання пошуку

Версія: робочі файли ЛР 4.1, після виправлень. Підсумковий Git-хеш додається
користувачкою після перенесення до наявного репозиторію. Node v24.22.1.
Вимірюється selectBookings для запиту «Олександр», serviceId=all, sort=date-asc.
Використано 2 початкові записи, 100 прогрівальних викликів, 7 серій по 1000 викликів.
Середній час одного виклику в серіях, мс:
0.002171; 0.001852; 0.001485; 0.001634; 0.001461; 0.001543; 0.001430.
Медіана: 0.001543 мс. Команда повторення: npm run measure.

Це вимірювання JavaScript-обчислення в Node, не jsdom і не браузерний Profiler.
Воно не включає React, DOM, малювання, навігацію або 600 мс mock.
Не порівнювали dev із production та не заявляли прискорення після рефакторингу.
На цьому невеликому наборі не зафіксовано дорогого обчислення пошуку;
додаткові memo/useMemo/useCallback не внесено. Зі збільшенням набору потрібне нове вимірювання.
Наявні useMemo/useCallback з попередніх етапів не подані як нова оптимізація.

Реальний браузер недоступний у середовищі підготовки. Тому повна взаємодія
пошуку та читабельність UI не позначені як перевірені браузером.
Для остаточної перевірки у dev відкрийте React Developer Tools → Profiler,
запишіть введення пошуку «Олександр» 3 рази на тому самому наборі записів.
Запишіть кількість commits, actualDuration та baseDuration, якщо вони доступні.
Зупиніть запис; не підставляйте наведені Node-числа замість Profiler-результатів.
Сам Profiler додає накладні витрати. Після нього окремо пройдіть production preview.
