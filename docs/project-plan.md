# План сайту барбершопу — ЛР 3.2

## Головна сутність: запис клієнта

Запис є локальним об’єктом, який пов’язує клієнта з послугою, бажаними датою й часом та необов’язковими побажаннями. Джерело даних — асинхронний mock із localStorage; провайдер зберігає підтверджений знімок для інтерфейсу. Записи зберігаються після перезавантаження в тому самому origin. API адаптер підготовлений без фактичного підключення.

| Поле | Тип | Обов’язкове | Правило |
| --- | --- | --- | --- |
| id | string | Так, системне | Унікальний ідентифікатор, створюється під час додавання |
| clientName | string | Так | Після обрізання пробілів — 2–60 символів |
| phone | string | Так | 10–20 цифр; допускаються +, пробіли, дужки й дефіси |
| serviceId | string | Так | Має відповідати одній із послуг у каталозі |
| date | string | Так | ISO-дата `YYYY-MM-DD`, не раніше поточної дати |
| time | string | Так | Час у форматі `HH:mm` |
| notes | string | Ні | До 300 символів |
| createdAt | string | Так, системне | ISO-час створення |
| updatedAt | string | Ні, системне | ISO-час останнього оновлення |

## Маршрути

| Шлях | Призначення |
| --- | --- |
| `/` | Головна |
| `/services` | Каталог послуг, пошук, категорія, сортування |
| `/bookings` | Список записів, пошук, фільтр за послугою, сортування |
| `/bookings/new` | Створення запису; підтримує `?serviceId=...` |
| `/bookings/:id` | Деталі одного запису |
| `/bookings/:id/edit` | Редагування запису за id |
| `*` | Сторінка 404 |

## Стан

- `BookingsContext` — спільна колекція, операції CRUD та повідомлення.
- `BookingForm` — локальна чернетка одного редагування; при помилках введення не очищується.
- Параметри URL `q`, `serviceId`, `category`, `sort` — стан подання списків, а не поля сутності.
- Каталог послуг у `src/data/services.js` є статичним довідником.

## Межі

Немає сервера, бази даних, автентифікації, підтвердження реальної доступності майстра або бронювання часу. Початкові записи — демонстраційні дані для перевірки CRUD.

## Підсумок ЛР 3.2

Реалізовано повний async CRUD, збереження, керовані відмови, повтор читання, блокування подвійного подання та захист застарілих відповідей. Наступні розширення до цієї роботи не входять.
