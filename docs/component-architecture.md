# Архітектура лабораторної 3.2

Сторінки та BookingForm → BookingsProvider / useBookings → bookingService → mock або API.
Mock → localStorage; API → fetch і сумісний зовнішній REST сервіс.

Компоненти відповідають за поля, повідомлення і навігацію.
BookingForm зберігає чернетку локально, блокує повтор і очікує onSubmit.
Провайдер володіє підтвердженим знімком, статусом, повтором та послідовними командами.
Сервіс перевіряє команди й відповіді, читає та підтверджує запис.
BookingsGate приховує розділ до завершення читання, тому деталі не показують
«не знайдено» передчасно. Оновлення доступне у списку, не в редакторі.

reload скасовує попередній запит і перевіряє його номер перед застосуванням.
Запис захищений ref-блокуванням; колекція змінюється лише після успіху сервісу.
Деталі й редактор беруть записи з того самого знімка. Окремий useBookingRecord
підготовлено та перевірено для досліду; у фінальні деталі його не підключено.
usePageActive захищає перехід після відповіді вже закритої сторінки або іншого id.
StrictMode збережений. Зміни інших клієнтів отримуються тільки явним повтором читання.
