# Перевірка лабораторної 3.2

Виконано npm run build — успішно. npm run lint — без помилок, 3 попередження
стосовно структури та ефекту провайдера; вони не блокують збірку.

Цільові сценарії виконано з реальними React-компонентами в моделюванні DOM
(jsdom); це не перевірка вигляду у звичайному браузері. Окремий Chromium у
середовищі виконання недоступний через системне обмеження socket.
Тимчасові засоби перевірки не додані як залежності студентського проєкту.

| Сценарій | Фактичний результат у DOM-середовищі |
| --- | --- |
| Початкове читання | Спочатку loading, потім колекція |
| getAll відмовляє один раз | Помилка; повтор відновлює список |
| create відмовляє | Ім’я та інші поля залишаються у формі |
| Два submit поспіль | Створений один запис |
| Повторне монтування застосунку | Запис читається зі сховища |
| update відмовляє, потім успішний повтор | Чернетка збережена, id незмінний, деталі оновлені |
| Видалення скасоване або відмовлене | Запис залишається |
| Успішне видалення | Перехід до оновленого списку |
| Пошук без збігів та скидання | Окремий порожній результат, потім записи |
| Повільний getById A → швидкий B | Хук залишає B навіть коли A ігнорує signal |
| Видалення всіх записів, повторний запуск | Залишається [], приклади не відновлюються |
| Невідомий id | Відсутній запис після читання |
| API 204 та 404 із підміненою fetch | Немає JSON для 204; 404 → NOT_FOUND |

Mock перевірено виконанням; API адаптер підготовлено за контрактом;
фактичне підключення ще не виконано. HTTP/CORS зовнішнього сервера не перевірено.
Для браузерної перевірки та скріншотів див. README.md і позначки у Word-звіті.

Виявлена проблема попередньої роботи: обробники синхронно читали result.ok.
Після переходу на Promise це було б undefined і перехід не відбувався б.
Виправлення: async/await на рівнях сервісу, провайдера, сторінки й форми;
успіх показується лише після завершення запису.
