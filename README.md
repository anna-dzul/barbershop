# Барбершоп — лабораторна робота 3.2

Робота з даними, асинхронними запитами та інтеграція із сервісами.
Продовження наданої лабораторної 3.1. Головна сутність — запис клієнта.

## Запуск у Windows
1. Встановіть Node.js 24 LTS, якщо його немає. Повторно відкрийте VS Code після встановлення.
2. Розпакуйте ZIP повністю через «Видобути все». Не відкривайте сайт усередині архіву.
3. У VS Code: Файл → Відкрити папку → barbershop_lab32.
   У цій папці мають бути package.json, src та public.
4. Термінал → Новий термінал. Виконайте `npm install` і дочекайтеся завершення.
5. За бажанням скопіюйте .env.example як .env.local. Для mock це не обов’язково:
   якщо змінних немає, застосунок сам обирає mock.
6. Виконайте `npm run dev -- --port 5173 --strictPort`.
7. Відкрийте адресу Local із термінала, зазвичай http://localhost:5173.
   Не запускайте index.html подвійним клацанням.
8. Для зупинки натисніть Ctrl+C у терміналі.
Якщо PowerShell блокує npm.ps1, оберіть у терміналі профіль Command Prompt
або використовуйте npm.cmd замість npm. Якщо порт зайнятий, спочатку зупиніть
попередній Vite. Для збережених даних використовуйте той самий хост і порт.

## Основні сторінки
`/services` — послуги, `/bookings` — записи, `/bookings/new` — форма,
`/bookings/:id` — деталі, `/bookings/:id/edit` — редагування.
Дизайн, каталог, поля та URL-фільтри з попередньої роботи збережені.

## Джерело та конфігурація
У .env.example: VITE_DATA_SOURCE=mock та порожня VITE_API_BASE_URL.
Вибір адаптера виконує src/services/bookingService.js.
Mock зберігає записи у localStorage за ключем barbershop.bookings.v1.
Дані переживають перезавантаження в тому самому браузері та origin.
Початкові два записи використовуються лише коли ключ відсутній; [] не скидається.
Сховище не синхронізується автоматично між вкладками або пристроями.
Це заявка на бажаний візит, без перевірки зайнятості майстра чи підтвердження бронювання.
API адаптер підготовлено; фактичне підключення до зовнішнього API не виконано.
Для сумісного сервісу потрібні VITE_DATA_SOURCE=api та його реальна базова адреса.
Перезапустіть Vite після зміни env. Не додавайте секрети у VITE_ змінні.

## Перевірка помилок у браузері
У режимі npm run dev відкрийте F12 → Console.
Введіть команду, натисніть Enter, потім виконайте дію на сайті:
- `barbershopMock.failNext("getAll")` — на списку натисніть «Оновити дані».
  З’явиться помилка; «Спробувати ще раз» відновить дані.
- `barbershopMock.failNext("create")` — подайте заповнену нову форму.
- `barbershopMock.failNext("update")` — збережіть редагований запис.
- `barbershopMock.failNext("delete")` — натисніть видалення й підтвердіть.
Відмова одноразова й відбувається до запису в сховище. Повторіть дію свідомо.
Якщо браузер блокує вставлення в консоль, наберіть коротку команду вручну.
Затримка: `barbershopMock.setDelay(2500)`; повернути: `barbershopMock.setDelay(600)`.
На повільній формі кнопка та поля блокуються, успішний перехід відбувається після запису.
Ці команди доступні лише під час розробки з mock; додаткових кнопок на сайті немає.

## Перевірка getById
Основні деталі читають спільний знімок провайдера. Окремий хук
src/hooks/useBookingRecord.js підготовлений для досліду, не створює другу копію у звичайному UI.
Для ручної перевірки скасування у Console введіть послідовно:
```js
const { mockBookingService } = await import('/src/services/mockBookingService.js');
const first = new AbortController();
const oldRead = mockBookingService.getById('booking-demo-1', { signal: first.signal }).catch(e => e.name);
first.abort();
await mockBookingService.getById('booking-demo-2');
await oldRead;
```
Другий виклик поверне актуальний запис, oldRead — AbortError.
Виконуйте до видалення демонстраційних записів, або підставте наявні id.
Хук додатково ігнорує застарілу відповідь навіть якщо сервіс не підтримав abort:
це перевірено виконанням React-компонента у DOM-середовищі з переходом A → B.

## Той самий Git репозиторій
У наданому архіві немає .git і посилання на віддалений репозиторій.
Тому історію та підсумковий коміт не вигадано. Відкрийте свою попередню папку,
яка вже підключена до Git, і перенесіть до неї файли цієї роботи,
зберігши наявну .git. Не копіюйте node_modules, dist та .env.local.
Далі в терміналі попередньої папки:
```sh
git status
git switch -c lab-3-2-services
git diff
git add src docs README.md .env.example package.json package-lock.json .gitignore
git commit -m "Add asynchronous booking services and data integration"
git log -1 --oneline
git remote -v
```
Якщо гілка вже є: git switch lab-3-2-services.
Вставте URL свого репозиторію та хеш створеного коміту у позначені місця звіту.
Публікацію виконайте у звичний для вашого репозиторію спосіб.
