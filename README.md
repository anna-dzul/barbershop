# Барбершоп — лабораторна робота 4.1

Інтеграція, тестування, оптимізація та підготовка завершеного ReactJS застосунку.
Це продовження версії 3.2: тема, дизайн, каталог, маршрути та модель збережені.
Репозиторій користувача: https://github.com/anna-dzul/barbershop
Попередній відомий локальний коміт: 3b2c7ff. Новий коміт створюється після перенесення файлів.

## Найпростіший запуск у Windows
1. Розпакуйте ZIP через «Видобути все». Знайдіть папку barbershop_lab41,
   у якій лежить package.json (не відкривайте лише вкладену src).
2. У VS Code: Файл → Відкрити папку → barbershop_lab41.
3. Термінал → Новий термінал. Перевірте `node -v`. Підходить Node.js 24 LTS.
4. Виконайте `npm ci` і дочекайтеся завершення. Залежності зафіксовано package-lock.json.
5. Виконайте `npm run dev`. Відкрийте адресу Local із термінала.
6. Зупиняйте сервер клавішами Ctrl+C. Не запускайте index.html подвійним кліком.
Якщо PowerShell блокує npm.ps1, використайте npm.cmd замість npm або профіль Command Prompt.

## Команди перевірки
В окремому терміналі тієї самої папки (кнопка + у VS Code):
```
npm run test:run
npm run lint
npm run build
npm run preview
```
Кожну команду вводьте окремим рядком і чекайте завершення попередньої.
Тести: очікується 6 файлів і 38 успішних перевірок. `npm test` — інтерактивний watch режим,
вихід клавішею q. Lint: немає помилок, залишаються 3 попередження у провайдері.
Build створює dist, preview подає вже зібрані файли, зазвичай http://localhost:4173.
Preview не є сервером для публічного розміщення. Ctrl+C зупиняє його.
Після змін коду перед повторним preview знову виконайте build.

## Що змінено в 4.1
- Додані Vitest, React Testing Library, user-event, jest-dom і jsdom.
- 38 тестів правил, фільтрації, форми, маршрутизованого сценарію, API та реального mock.
- Телефон перевіряється за кількістю цифр, а не довжиною рядка з пробілами.
- Перевіряється календарна дата та наявність послуги в каталозі.
- Некоректна форма фокусує перше помилкове поле й не звертається до збереження.
- Редактор передає лише редаговані поля без id та createdAt.
- Відбір винесений у selectBookings; список використовує загальний каталог services,
  а не його дубль. Пошук і сортування мають попередню поведінку.
- Додано вимірювання чистого обчислення пошуку: `npm run measure`.
Додаткову мемоізацію не вводили без виміряної потреби.

## Джерело та дані
Режим за замовчуванням — mock, із локальним збереженням у цьому браузері.
.env.example:
```
VITE_DATA_SOURCE=mock
VITE_API_BASE_URL=
```
Можна скопіювати його як .env.local; для запуску mock це не обов’язково.
У VITE_ не зберігаються секрети. Режим api потребує власного сумісного сервісу:
підготовлений адаптер ще не є фактично підключеним backend.
Ключ localStorage: barbershop.bookings.v1. Видалена порожня колекція лишається [].
Зміна порту/хоста змінює origin: dev та preview можуть містити різні локальні дані.
Не очищуйте все сховище. Для свідомого відновлення прикладів після збереження
потрібних даних видаліть тільки зазначений ключ через F12 → Application → Local Storage.
Запис не перевіряє реальну зайнятість майстра і не є підтвердженням бронювання.

## Контрольований збій для демонстрації
Тільки у dev/mock: F12 → Console → набрати вручну:
`barbershopMock.failNext("getAll")`, Enter, на сайті «Оновити дані».
«Спробувати ще раз» відновить читання. Для форми: операції create або update;
для видалення — delete. Дані не змінюються до цієї навчальної відмови.
Команда `barbershopMock.setDelay(2500)` уповільнює mock, повернення — setDelay(600).
У production preview ці навчальні команди недоступні.

## Ручний прохід production preview
1. Відкрийте адресу preview → Послуги → «Записатися» біля потрібної послуги.
2. Подайте порожню форму. Повинні бути пояснення й фокус на першому полі.
3. Заповніть тестові дані: ім’я «Тестовий Клієнт», телефон +380671234567,
   будь-яка наявна послуга, МАЙБУТНЯ дата, час 12:30, побажання «Перевірка 4.1».
4. Створіть запис. Дочекайтеся деталей і повідомлення успіху.
5. Скопіюйте URL деталей; перезавантажте його. Дані повинні зберегтися.
6. Відредагуйте побажання, збережіть і перевірте оновлені деталі та список.
7. Введіть пошук без збігів і скиньте його. Записи повинні відновитися.
8. На деталях скасуйте видалення, потім видаліть саме тестовий запис із підтвердженням.
9. Відкрийте /unknown і /bookings/missing — мають бути різні повідомлення.
Не видаляйте важливі робочі записи під час демонстрації.

## Продуктивність
`npm run measure` відтворює Node-вимірювання selectBookings на двох початкових записах:
7 серій по 1000 викликів після прогріву. Воно не вимірює React, DOM або швидкість браузера.
Фактичний результат та обмеження: docs/performance.md.
За бажанням перевірте введення пошуку через браузерний Profiler (див. інструкцію звіту).
Не записуйте штучні 600 мс mock як час рендерингу.

## Що перевірено тут
38 тестів пройдено; build успішний; HTTP preview видає HTML прямих адрес і JS/CSS.
Сам зібраний JavaScript виконав сценарій каталог → створення → редагування →
скасування та підтвердження видалення в jsdom, з реальним mock і localStorage.
Це не реальний браузер і не вимірювання розкладки/малювання.
Звичайний браузер у середовищі підготовки був недоступний; візуальний прохід і
Profiler залишені для виконання користувачкою, без вигаданих результатів.

## Збереження в тому самому Git репозиторії
Відкрийте E:\Універ\ТКПЗ\barbershop_git — папку, у якій створювали коміт 3b2c7ff.
Перенесіть туди вміст barbershop_lab41, зберігши наявну .git.
Не переносіть node_modules, dist і .env.local. У цій папці виконайте npm ci та перевірки.
Команди вводьте ОКРЕМО, щоразу натискаючи Enter:
```
git status
git diff
git add src docs scripts README.md ІНСТРУКЦІЯ.txt package.json package-lock.json vite.config.js .gitignore Dockerfile compose.yaml .dockerignore
git commit -m "Integrate and test coursework application"
git log -1 --oneline
git push -u origin main
```
Хеш із git log вставте в звіт. 3b2c7ff — попередня робота, не підсумковий коміт 4.1.
Якщо git status каже not a git repository, відкрито неправильну папку.
Не виконуйте git init і не клонуйте репозиторій повторно для кожної лабораторної.

## Додатковий контейнерний запуск
Основний перевірений спосіб — локальний Node/npm. Dockerfile і compose.yaml
дають базовий workflow, але Docker у середовищі підготовки не запускався.
Якщо Docker Desktop уже встановлений: docker compose up --build.
Тести: docker compose run --rm web npm run test:run.
Build: docker compose run --rm web npm run build.
Preview: docker compose run --rm -p 4173:4173 web npm run preview -- --host 0.0.0.0 --port 4173 --strictPort.
Відкрийте localhost:4173. Для цієї роботи встановлювати Docker замість робочого Node не потрібно.
